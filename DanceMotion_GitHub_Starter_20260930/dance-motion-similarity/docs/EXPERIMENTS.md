# Experiment guide

These are research scripts, not a self-contained test suite. Run them from the repository root. Many require local videos, resolution-specific OpenPose caches, official metadata, or CSVs generated by earlier stages. They can perform expensive extraction and write or overwrite result folders.

| Script | Purpose |
|---|---|
| `phase3_calibration.py` | Establish D/E distributions for selected `ch01–ch03` pairs |
| `phase3_smoothing_diagnostic.py` | Compare raw and three-frame median angle errors on the same DTW paths |
| `phase3_path_weighting_diagnostic.py` | Compare path-pair averaging with reference/test-balanced averaging |
| `phase3_score_architecture_calibration.py` | Compare candidate raw metrics using block-wise holdout |
| `phase3_unseen_choreo_validation.py` | Evaluate the historical pose-distance architecture on `ch04–ch06` |
| `phase_pose_distance_diagnostic.py` | Diagnose extreme normalized-coordinate distances |
| `phase3_robust_normalization_ab.py` | Compare frame-wise and sequence-median scale normalization |
| `phase3_normalization_downstream_validation.py` | Measure normalization effects on angle errors and timing |
| `phase3_score_mapping_calibration.py` | Fit logistic engineering anchors using development comparisons |
| `phase3_final_validation.py` | Apply the frozen mapping to `ch07–ch10` |
| `phase3_resolution_downstream_validation.py` | Compare `432x240` and `-1x368` with scoring settings fixed |
| `phase3_final_regression_check.py` | Compare current V1.2 with stored expectations on `ch01` and `ch10` |

## Dependencies

Historical scripts load `Dance_Motion_Similarity_Evaluation_V1.1_final.py`; resolution and final-regression scripts load V1.2. Configure the corresponding OpenPose path before use. The early `Dance_Motion_Similarity_Evaluation_V1.1.py` is a development script with top-level work, not a general-purpose importable library.

Typical required assets include:

- Videos under `data/aistpp/videos/`.
- `data/aistpp/videos/refined_10M_all_video_url.csv` for scripts validating official filenames.
- `phase3_calibration_distribution/pair_summary.csv` and `phase3_smoothing_diagnostic/smoothing_pair_results.csv` for architecture comparisons.
- `phase3_normalization_downstream/normalization_downstream_pair_results.csv` for score mapping.
- `phase3_score_mapping/score_mapping_parameters.csv` and `development_score_results.csv` for final validation.

These input/output CSVs are not included. Read each script's input checks before launching it. Earlier experiments used `432x240`; do not silently change all historical scripts to the current resolution when reproducing them.

## Current regression command

After installing OpenPose and providing the exact required videos/caches:

```powershell
python phase3_final_regression_check.py
```

This checks fixed settings and compares measured values with source-recorded targets. Different model builds or freshly extracted skeletons may differ. A mismatch should be investigated, not resolved by editing expected numbers merely to obtain PASS. Read the printed PASS/FAIL result: the script does not consistently express failure through a nonzero process exit code.

For resolution A/B testing:

```powershell
python phase3_resolution_downstream_validation.py
```

Keep input videos, model weights, sampling, confidence threshold, normalization, smoothing, DTW, and score mapping fixed. Record runtime as well as raw visibility and downstream errors. The executable pipeline processes the video before Python selects every second JSON frame, so `FRAME_STEP=2` does not itself halve executable inference time.
